12. El concepto de estructura de control iterativa

Suponed que estamos cocinando una salsa bechamel. Quizá nunca lo hayáis hecho, pero para prepararla hay que freír un poco de harina en mantequilla y, luego, añadir leche y remover. No pararemos de remover a fuego lento hasta que la salsa esté ligada, por lo que repetiremos muchas veces la siguiente secuencia:

Remover la salsa un rato.
Comprobar si la salsa está ligada. Si no lo está, volveremos a remover. En cambio, si la salsa está ligada, ya habremos acabado de cocinar la receta. 

Lo que acabamos de describir es un bucle, en el que se repite la misma secuencia (1. Remover, 2. Comprobar si la salsa está ligada) hasta que se haya acabado de cocinar la salsa.

Lo que acabamos de introducir es una estructura iterativa en la que una acción se realiza «mientras» se cumpla una condición.

Una estructura de control iterativa, también conocida como bucle, es una estructura en la que unas instrucciones del algoritmo o programa se repiten mientras se cumpla una condición.

Observad que hasta ahora los programas que hemos hecho han sido una secuencia de instrucciones: primero se ejecuta una instrucción, después se ejecuta una segunda, luego una tercera, etc.

En este caso no es así, el flujo del algoritmo o programa depende de una condición. Si la condición se cumple, se repiten unas acciones; si no se cumple, se sigue adelante. Por esta razón se denomina estructura de control del flujo del algoritmo o programa: el flujo del algoritmo o programa se estructura de manera que no es una secuencia de instrucciones, sino que depende de que se cumpla una condición. 

La estructura de control iterativa es muy interesante, porque nos permite ejecutar muchas veces un bloque de instrucciones. El número de veces que se ejecute depende del propio problema que hay que resolver. 

Imaginemos ahora que queremos hacer una tortilla de patatas, para lo cual tenemos que pelar, limpiar y cortar cinco patatas. Podemos utilizar esta estructura para diseñar un algoritmo que describa este proceso. Podemos definir un contador y repetir el proceso las veces que haga falta. En este caso, el diagrama de flujo sería diferente, porque sabemos de antemano cuántas patatas tenemos que preparar.
