Introducción

Como ya hemos visto de manera reiterada en las últimas unidades, el concepto de modularidad se basa en dividir el código en partes más pequeñas que tengan una funcionalidad concreta. En programación, esta división permite, por un lado, hacer más legible el código y, por otro lado, reutilizar partes del código en diferentes aplicaciones. La modularización más simple es el uso de funciones y acciones, pero, a medida que necesitamos trabajar con códigos más grandes, puede ser necesario dar algún paso más. 

En concreto, podemos plantear la posibilidad de separar las acciones y las funciones de nuestro código en diferentes ficheros. Hasta ahora, hemos trabajado con un único fichero de código fuente (main.c), pero no es imprescindible. De hecho, lo más habitual es trabajar con distintos ficheros, cada uno de los cuales tiene una parte concreta del código. Al separar las funciones y las acciones en distintos ficheros, podemos reutilizar el mismo código en programas diferentes: solo tenemos que copiarlo a otro programa y añadirlo a este.

En esta unidad, explicaremos cómo podemos hacerlo en C.

 

1. Cabecera de una función

Hasta ahora, hemos visto cómo generar acciones y funciones en C. Un ejemplo ha sido la función factorial:

#include <stdio.h>

/* Define the factorial function */
int factorial(int number) {

    int fact;
    int i;
    fact = 1;
    i = 1;

    while (i <= number)  {
        fact = fact * i;
        i++;
    }
    return fact;
}

/* Define the main program */ 
int main() {

    int totalNumColors;
    int colorsToCombine;
    int result;

    scanf("%d", &totalNumColors);
    scanf("%d", &colorsToCombine);

    /* Calculate the combinations of n over m, calling the function factorial 3 different times */ 
    result = factorial(totalNumColors) / 
        (factorial(colorsToCombine) * factorial(totalNumColors-colorsToCombine));

    printf("%d ", result);

    return 0;
}

En unidades anteriores, hemos explicado que la primera línea de la definición de la función se llama cabecera, en la cual se explicitan el nombre de la función, los parámetros que acepta y el tipo de valor que devuelve:

int factorial(int number)

Fijaos en que, en el programa, primero se define la función factorial, de manera que, cuando se llama en el programa main, el compilador ya la ha leído y sabe lo que tiene que hacer cuando se llama. 

La definición también se podría hacer de otra manera:

#include <stdio.h>

/* Header of function factorial */
int factorial(int number);

/* Define the main program */ 
int main() {

    int totalNumColors;
    int colorsToCombine;
    int result;

    scanf("%d", &totalNumColors);
    scanf("%d", &colorsToCombine);

    /* Calculate the combinations of n over m, calling the function factorial 3 different times */ 
    result = factorial(totalNumColors) / 
        (factorial(colorsToCombine) * factorial(totalNumColors-colorsToCombine));

    printf("%d ", result);

    return 0;
}

/* Define the factorial function */
int factorial(int number) {

    int fact;
    int i;
    fact = 1;
    i = 1;

    while (i <= number)  {
        fact = fact * i;
        i++;
    }
    return fact;
}

Fijaos en que, aquí, la definición se ha hecho de manera ligeramente diferente:

Hemos incluido la cabecera de la función factorial.
Hemos definido el programa main, donde se llama a la función factorial.
Hemos definido la función factorial.

En este caso, cuando el compilador lee la función main, aún no ha leído la función factorial, que va detrás del programa main. Pero sí que ha leído la cabecera y sabe cómo hay que llamar a la función.

Aunque la diferencia en este punto pueda parecer insignificante, es crucial para lo que vamos a explicar a continuación.

 

2. Múltiples ficheros de código

A medida que nuestro programa crece, puede resultar interesante (y necesario) dividirlo en múltiples ficheros. 

Cuando modulamos (dividimos) un programa en múltiples ficheros, seguimos esta distribución:

main.c: contiene el bloque de código principal.
nombreFichero.h: tiene las cabeceras de las funciones y las acciones, las constantes y otros tipos de datos (enumerativos, tuplas, etc.) requeridos por el programa.
nombreFichero.c: contiene la codificación de las funciones y las acciones.

Mantenemos el nombre del fichero principal del programa, main.c. El nombre de los otros dos ficheros, nombreFichero.h y nombreFichero.c, cambian en función del programa que estemos codificando. Por ejemplo, en el caso que trataremos a continuación, estos dos ficheros se llaman showHelloWorld.h y showHelloWorld.c.

Imaginemos, por ejemplo, que tenemos un proyecto llamado Modularity. Queremos que este programa tenga una función que se llame HelloWorld y que escriba por pantalla esa frase, y que se llame desde el programa principal. Sería algo así:

#include <stdio.h>

/* Function and action definition */
void showHelloMessage() {
    printf("hello world\n");
}

/* Main program */
int main() {
    showHelloMessage();
    return 0;
}

Imaginemos ahora que queremos poner la función showHelloMessage en otro fichero para poder utilizarla en diferentes programas. Entonces tendríamos dos ficheros:

main.c
	
showHelloWorld.c


#include <stdio.h>


/* Main program */
int main() {
    showHelloMessage();
    return 0;
}

	
#include <stdio.h>

/* Function and action definition */
void showHelloMessage() {
    printf("hello world\n");
}

Fijaos en que, en este punto, vamos a tener un problema. Cuando el compilador lea el programa en main.c, va a llegar a la llamada de showHelloMessage y antes no habrá leído una cabecera para esa llamada, por lo que no sabrá cómo se llama y lanzará un error. En otras palabras, necesitamos incluir la cabecera de la función en el fichero main.c para que el compilador la conozca en el momento de llamarla. 

Nosotros hemos escrito la función showHelloMessage; así que conocemos la cabecera y podríamos añadirla a mano. Pero, en general, se hace lo siguiente:

Se crea el fichero .c con el código de la función (de extensión .c).
Se crea otro que tiene extensión .h (headers o cabeceras) con las cabeceras de las funciones que hay en el fichero .c.
En el fichero main.c, se incluye el fichero .h con las cabeceras.

En el programa anterior quedaría de la siguiente manera:

main.c
	
showHelloWorld.c
	
showHelloWorld.h


#include <stdio.h>

#include "showHelloWorld.h"

/* Main program */
int main() {
    showHelloMessage();
    return 0;
}

	
#include <stdio.h>

/* Function and action definition */
void showHelloMessage() {
    printf("hello world\n");
}
	
/* Function and action headers */
void showHelloMessage();

Este programa hace lo siguiente:

El fichero principal es siempre main.c.
En el programa principal, hemos añadido un fichero de cabeceras «showHelloWorld.h», donde está la cabecera de la función showHelloWorld. Cuando el compilador lee main.c, abre también el fichero de cabeceras, y cuando en el programa main.c se llama a la función, el compilador ya la conoce. 
En el fichero showHelloWorld.c está la función que tiene ese nombre.

Fijaos en que, si ahora queremos añadir la función en otro programa, solo tenemos que añadir los ficheros .c y .h.

 

3. Modularidad en CodeLite

A continuación, explicaremos paso a paso cómo generar un programa modular como el que hemos descrito anteriormente. Para ello, una vez que estamos en CodeLite:

Cerramos cualquier workspace abierto. Si hay algún workspace abierto, lo cerramos: «Workspace» -> «Close Workspace»
Creamos un nuevo workspace (espacio de trabajo). «Workspace» -> «New Workspace». Escribimos el nombre del espacio de trabajo: showHelloWorld.
Creamos un nuevo proyecto. En este punto, puede ser difícil ver la diferencia entre un espacio de trabajo y un proyecto. Simplemente quedaos con la idea de que un único espacio de trabajo puede tener varios proyectos, mientras que cada proyecto se suele relacionar con un programa. A veces, es interesante trabajar con diferentes programas a la vez, pero ya lo iréis viendo a medida que os convirtáis en personas expertas en programación.
«Workspace» -> «New Project»
En este momento, CodeLite ya nos propone un nombre para el proyecto, que es el que utilizaremos: showHelloWorld.
También dejaremos las otras opciones igual.

Ya tenemos un workspace y un proyecto, y los dos se llaman showHelloWorld. En el proyecto, tenemos un directorio que se llama «src» (source, que es donde están los programas fuente o de código), en el que está el programa main.c que nos ha generado CodeLite para empezar con un programa. 

Ahora, crearemos un nuevo fichero de código dentro de la carpeta «src»:

Creamos un nuevo fichero de código. Clicamos con el botón derecho del ratón sobre la carpeta «src».
«Add a new file».
El nombre del fichero será showHelloWorld.c.
Fijaos en que la opción que nos da para empezar es una extensión .cpp (C plus plus o C++). Queremos que sea un fichero de código C.
Añadimos el código al nuevo fichero. Podemos copiar el código de más arriba.
Creamos un nuevo fichero de cabeceras. Normalmente, los ficheros de cabeceras y los de código no se guardan en la misma carpeta. Los de cabeceras se guardan en una llamada include. En este caso, aún no ha sido creada, así que lo haremos:
Creamos una carpeta para los ficheros de cabeceras en el proyecto. Clicamos con el botón derecho en el nombre del proyecto.
«New Virtual Folder»
Ponemos include como nombre.
Creamos el nuevo fichero de cabeceras. Clicamos con el botón derecho sobre el nombre de la carpeta «header».
«Add a new file»
showHelloWorld.h
Añadimos las cabeceras al nuevo fichero. Podemos copiar la cabecera que había más arriba.
Modificamos el programa principal. Ahora que ya tenemos el código de la nueva función en su fichero y la cabecera en el otro, podemos añadirlo al programa principal. 
Incluimos el fichero de cabecera:
#include "showHelloWorld.h"
Modificamos el programa para que llame a la función:

showHelloMessage();

(Fijaos en que el código de los tres ficheros ha de quedar como explicitábamos un poco más arriba).

Ahora podemos compilar y ejecutar. 

 

Resumen

 

Una cabecera se puede utilizar para informar al compilador sobre cómo se llama una función.
Usar múltiples ficheros de código puede ser una buena opción para reutilizar algunas funciones. 
Cuando modulamos un programa en múltiples ficheros, seguimos esta distribución:
main.c: contiene el bloque de código principal.
nombreFichero.h: tiene las cabeceras de las funciones y acciones, las constantes y los tipos de datos (enumerativos, tuplas, etc.) requeridos por el programa.
nombreFichero.c: contiene la codificación de las funciones y acciones.
El nombre de los ficheros nombreFichero.h y nombreFichero.c se adecuan a cada programa en particular. El nombre del fichero principal siempre es main.c.
En CodeLite podemos usar estos ficheros para no tener que reescribir código.
