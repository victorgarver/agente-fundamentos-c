Resumen

 

1. Secuencias de datos

Ya conocemos las estructuras de código secuencial, alternativa e iterativa. Todos los programas que existen utilizan una de estas tres estructuras. No obstante, dado que las soluciones a un problema son múltiples, tenemos que intentar generar la mejor solución posible.

¿Cómo sabemos si una solución es mejor que otra?

Hay varios conceptos o características de la solución que debemos tener en cuenta a la hora de proponer la mejor. Algunos de estos conceptos pueden ser:

Eficiencia: que el algoritmo diseñado minimice el uso de los recursos del ordenador para encontrar la solución correcta.
Fiabilidad: que el resultado que la solución nos da sea correcto. 

Pero estos no son los únicos criterios en los que nos podemos fijar, ya que puede haber otros, como la usabilidad, la seguridad, etc.

En esta unidad, introduciremos conceptos que nos permitirán mejorar o efectuar una optimización elemental en una situación concreta: el procesamiento de una secuencia de datos. Empezaremos por entender qué es una secuencia de datos. 

Una secuencia de datos es un conjunto de elementos que contienen datos o información y que están ordenados de una manera determinada. Los datos que cada uno de estos elementos contiene pueden ser de diferentes tipos (números enteros o reales; una mezcla de diferentes tipos, como en el caso de una tupla, etc.), pero el número de elementos es siempre finito: no tenemos infinitos datos.

Una secuencia de datos es algo muy habitual. Estos son algunos ejemplos de secuencias de datos:

Una lista de la compra: tenemos una lista de elementos que queremos comprar. El dato que guarda cada elemento es el nombre del elemento de la lista.
Un acta de notas de una asignatura: tenemos una lista de estudiantes y, para cada elemento de la lista, disponemos del nombre y de los apellidos, quizá de un identificador, y de la nota que ha obtenido en esa asignatura. 

Como veis, aunque la definición de secuencia de datos que hemos efectuado puede parecer muy técnica, el concepto nos resuelta muy familiar, ya que se utiliza de manera cotidiana en nuestra vida. 

 

2. Esquemas algorítmicos

Como hemos indicado, en esta unidad hablaremos sobre formas de optimizar el procesamiento de una secuencia de datos. 

Introduciremos patrones o maneras de resolver un problema determinado que se ajusta a unas características concretas: cómo podemos procesar una secuencia de datos. Os propondremos dos situaciones que ilustran los dos esquemas algorítmicos que trabajaremos. Aunque hay otras que se pueden ajustar mejor a situaciones concretas y que pueden ser más eficientes, estas dos estructuras son un buen comienzo en esta asignatura.

Imaginemos a un profesor de la UOC que debe corregir la PEC1 del aula. El proceso consiste en ir corrigiendo una a una todas las PEC1 que los estudiantes de su aula le han entregado. El profesor recorre todas las PEC, que están ordenadas según un criterio determinado (por ejemplo, orden alfabético del apellido de los estudiantes u orden en el que las ha recibido). El profesor aplica el mismo procedimiento a cada una: corregirlas y evaluarlas. La tarea termina cuando todas las PEC estén corregidas y evaluadas. En este ejemplo, hemos descrito un recorrido a través de una secuencia de datos de un mismo tipo.

Imaginemos ahora que, una vez publicadas las calificaciones de la PEC1, unos estudiantes piden al profesor la revisión de su nota. El profesor deberá buscar las PEC de esos estudiantes de entre todas las PEC que se hayan entregado. Una vez que las encuentre, las revisará. El profesor hará una búsqueda de las PEC que hay que revisar dentro de una secuencia o conjunto de PEC.

Una vez entendido el concepto subyacente a estas estructuras algorítmicas, a continuación, las explicaremos con más detalle.

 

2.1. Esquema de recorrido
Un algoritmo de recorrido, o esquema algorítmico de recorrido, es aquel en el que, sucesivamente (uno tras otro), se realiza un procesamiento determinado de todos los elementos de una secuencia. En esta estructura algorítmica, todos los elementos se procesan. 

Fijaos en que este esquema algorítmico presenta las siguientes características:

Una secuencia de datos en la que todos los elementos son del mismo tipo.
Un procesamiento de datos que es igual para todos los elementos de la secuencia.
La necesidad de saber cómo se acaba la secuencia.

 

Ejemplo 01

En este ejemplo, calculamos la temperatura media de una semana suponiendo que leemos por el canal de entrada la temperatura media de cada día.

Pseudocódigo
	
C



const
    NUM_WEEK_DAYS: integer = 7;
end const

algorithm averageTemp

    var
        temperature: real;
        sum: real;
        i: integer;
    end var

    i := 1;
    average := 0.0;

    while i ≤ NUM_WEEK_DAYS do
        temperature := readReal();
        sum := sum + temperature;
        i := i + 1;
    end while

    writeReal(sum / integerToReal(NUM_WEEK_DAYS));
end algorithm

	
#include <stdio.h>

#define NUM_WEEK_DAYS 7

int main() {

    float temperature;
    float sum;
    int i;

    i = 0;
    average = 0;

    while (i < NUM_WEEK_DAYS) {
        scanf("%f", &temperature);
        sum = sum + temperature;
        i = i + 1;
    }

    printf("%f", sum / double(NUM_WEEK_DAYS));
    return 0;
}

 

Ejemplo 02

En este ejemplo, cargamos las cifras de recaudación de cada una de las salas de un cine. Los datos son una secuencia de reales que se lee a través del canal estándar y se guarda en una tabla. El final de la secuencia se indica cuando el valor de la recaudación es -1.0.

Pseudocódigo
	
C



const
    MAX_THEATERS: integer = 20;  
    END_SEQ:  real = -1.0;
end const

type
    tTheater = record
        collect: vector[MAX_THEATERS] of real;
        numTheaters: integer;
    end record
end type

algorithm fillTable

    var
        movieTheater: tTheater;
        i:  integer;
        temp: real;
    end var

    movieTheater.numTheaters := 0;
    temp := readReal();  {we read the first number}

    while temp ≠ END_SEQ and movieTheater.numTheaters ≤ MAX_THEATERS do

        movieTheater.numTheaters := movieTheater.numTheaters + 1;
        movieTheater.collect[movieTheater.numTheaters] := temp;

        temp := readReal();
    end while

end algorithm

	
#include <stdio.h>

#define MAX_THEATERS 20
#define END_SEQ -1.0

typedef struct {
    float collect[MAX_THEATERS];
    int numTheaters;
} tTheater;

int main(){
    /* var definition */
    tTheater movieTheater;
    int i;
    float temp;
   
    /* table initialization */
    movieTheater.numTheaters = 0;
    scanf("%f", &temp);  /* read the first number */

    /* iteration while the read number is not -1 */
    while (temp != END_SEQ && movieTheater.numTheaters <= MAX_THEATERS) {
        /*Save the read number in the table*/
        movieTheater.collect[movieTheater.numTheaters] = temp;
        movieTheater.numTheaters = movieTheater.numTheaters + 1;
        scanf("%f", &temp);  
    }
    return 0;
}

Revisando el ejemplo anterior, podemos establecer que en una estructura algorítmica de recorrido siempre seguimos estos pasos:

1
	
Determinar el primer elemento

Necesitamos saber cuál es el primer elemento de la lista.

Por ejemplo, si la lista de elementos es un array, el primer elemento del array puede ser el primero que procesemos.

En los ejemplos anteriores, el primer elemento que se introduce por teclado es el primer elemento de la secuencia. 



2
	
Determinar el último elemento

Necesitamos saber cuál es el último elemento de la lista.

En el caso de que tratemos un array, deberíamos saber cuántos elementos hay en el array.
En el caso de que tratemos de una tabla, la propia tabla tendrá la información del número de elementos que contiene. 

En el primer ejemplo, el elemento 7 es el último.
En el segundo, se sabe que se han procesado todos los datos porque el usuario introduce un valor de recaudación de -1.0. La recaudación no puede ser negativa, y, por tanto, esto indica que ya no hay más datos.



3
	
Inicializar variables

En este momento realizamos cualquier operación que sea necesaria previamente al tratamiento de los datos. 

En el primer ejemplo, el cálculo de la media ha de empezar con un valor de la suma de los elementos igual a 0. También se genera un contador cuyo valor se inicia en 1 y que nos indicará qué elemento se está procesando. 
En el segundo, la suma de las recaudaciones también se inicializa a 0. Fijaos en que, en este caso, antes de entrar en el bucle, hay que leer el primer dato. Esto es así porque, según la condición del bucle, es el propio dato el que nos dice si la secuencia se ha acabado o no y si el bucle debe seguir o no.



4
	
Procesar los elementos

Uno por uno, a través de una estructura de control iterativa, se accede a cada uno de los datos que se deben procesar.

Cada vez que se procesa un elemento, se ha de revisar si hay más elementos que procesar o no. Este control se puede hacer de distintas maneras:

Se puede crear un índice que cuente cuántos elementos se han procesado. Cada vez que uno se procesa, se incrementa el valor del contador y se revisa si se ha llegado al número de elementos máximo de la secuencia (este es el caso del primer ejemplo). 
Se chequea el valor de una variable, de manera que, si tiene un valor concreto, se concluye que se ha acabado el procesamiento de datos (en el segundo ejemplo, esta situación se produce cuando el valor proporcionado por el usuario es -1.0).


5
	
Realizar el tratamiento final

Una vez que se han procesado todos los datos, se realiza cualquier acción que sea necesaria para obtener el resultado deseado. 

En el primer ejemplo, hay que dividir la suma de todos los elementos por el número de días. En el segundo, una vez que todos los datos hayan sido procesados, no hay que hacer nada más. 

Siempre que necesitemos hacer un tratamiento para una serie de datos de un mismo tipo que estén estructurados en forma de secuencia, podemos aplicar directamente el esquema de recorrido tal y como lo hemos presentado en estos ejemplos. 

 

2.2. Esquema de búsqueda
Un algoritmo de búsqueda, o esquema algorítmico de búsqueda, es aquel en el que el procesamiento de los datos solo se realiza sobre algunos de los elementos de la secuencia. En otras palabras, debemos buscar el elemento o los elementos de la secuencia que hay que procesar. 

 

Ejemplo 03

Algoritmo que, partiendo de un registro de las temperaturas medias de cada día de una semana —que leemos por el canal estándar—, averigua cuál es el primer día que ha helado. Es decir, el algoritmo efectúa una búsqueda en la secuencia de temperaturas diarias hasta encontrar el primer valor negativo.

Pseudocódigo
	
C



const
    NUM_WEEK_DAYS: integer = 7;
end const

algorithm didItFreeze

    var
        t: vector[NUM_WEEK_DAYS] of real;
        frost: boolean;
        i: integer;
    end var

    i := 1;
    frost := false;

    while i ≤ NUM_WEEK_DAYS and not frost do
        t[i] := readReal();
        if t[i] ≤ 0 then
            frost := true;
        end if
        i := i + 1:
    end while

    writeBoolean(frost);

end algorithm

	
#include <stdio.h>
#include <stdbool.h>

#define NUM_WEEK_DAYS 7

int main() {

    float t[NUM_WEEK_DAYS];
    bool frost;
    int i;

    i = 0;
    frost = false;

    while (i < NUM_WEEK_DAYS && !frost) {
        scanf("%f", &t[i]);
        if (t[i] < 0 ) {
            frost = true;
        }
        i = i + 1;
    }

    /* Equivalence in C language: 0 == false, 1 == true */
    printf("%d", frost);  

    return 0;
}

Observad que, en el ejemplo 03, cuando encontramos el primer caso de temperatura negativa, ya podemos dejar de buscar. No es necesario que sigamos revisando otra temperatura, puesto que solo queremos encontrar el primer día que ha helado, no cuántos. Si quisiéramos saber cuántos días ha helado, tendríamos que hacer un recorrido por todas las temperaturas.

En este ejemplo, estamos haciendo una búsqueda en un conjunto de datos (una secuencia de datos). Buscamos una temperatura negativa entre las siete temperaturas registradas de una semana.

Para buscar dentro de la secuencia, estamos utilizando un mismo esquema, que podríamos representar así:

1
	
Determinar el primer elemento

Necesitamos saber cuál es el primer elemento de la lista.

Por ejemplo, si la lista de elementos es un array, el primer elemento del array puede ser el primero que procesemos.

En el ejemplo anterior, el primer elemento que se introduce por teclado es el primer elemento de la secuencia. 



2
	
Determinar el último elemento

Necesitamos saber cuál es el último elemento de la lista.

En el ejemplo, el último elemento es el número 7, es decir, el número de días que hay en una semana.



3
	
Inicializar variables

En este momento realizamos cualquier operación que sea necesaria previamente al tratamiento de los datos. 

En el ejemplo, hemos creado dos variables:

Un contador, i, que nos informa de qué elemento estamos revisando.
Un indicador o flag que se inicializa a false, y que solo cambiará a true cuando encontremos un valor de temperatura negativo. 


4
	
Procesar los elementos

Uno por uno, a través de una estructura de control iterativa, se va accediendo a cada uno de los datos que se deben procesar.

A diferencia del caso de recorrido, el objetivo no es procesar todos los datos, sino encontrar uno en concreto que cumpla unas determinadas características. En el momento en el que se encuentre el elemento que se busca, el indicador se puede marcar como true.

Si el elemento no se encuentra, se procesarán todos los datos, y el indicador continuará siendo false. 



5
	
Realizar el tratamiento final

Una vez que se ha encontrado el elemento buscado, se realiza cualquier acción que sea necesaria para obtener el resultado deseado. 

En el primer ejemplo, hay que dividir la suma de todos los elementos por el número de días. En el segundo, una vez que todos los datos hayan sido procesados, no hay que hacer nada más. 

Fijaos en lo siguiente:

A diferencia del esquema de recorrido, donde tratamos todos los elementos, en el esquema de búsqueda recorremos únicamente la secuencia hasta encontrar un elemento que cumpla una determinada condición.
El esquema contempla la posibilidad de que la secuencia no contenga el elemento buscado.
El esquema prevé que la búsqueda termine por alguno de estos dos motivos: o bien encontramos el elemento buscado, o bien llegamos al final de la secuencia.

 

3. Ejemplos

 

3.1. Desplazamiento de elementos en un vector

Los desplazamientos en un vector se pueden producir cuando se añade o elimina un elemento de un vector. Al hacerlo, el resto de elementos se deben desplazar para acomodar el nuevo elemento o para ocupar el espacio que el elemento borrado ha dejado. 

 

Añadir un elemento

Si queremos añadir un elemento dentro del vector de una tabla en una posición que no sea la última, primero habrá que desplazar el resto de elementos una posición a la derecha.

Supongamos que tenemos un vector con valores numéricos que están ordenados en orden ascendente y queremos añadir un valor que es más pequeño que todos los otros. Entonces, deberemos hacer un hueco en la primera casilla y guardar allí el nuevo valor. 

Esquemáticamente, lo haríamos así:

Contenido inicial del vector de la tabla	
7	12	26	31

Preparación para acomodar el nuevo elemento	
...	7	12	26	31

Contenido final del vector de la tabla	
5	7	12	26	31

Como último paso, recordad que, al ser una tabla, debemos incrementar en 1 el atributo que contiene el tamaño de esta.

 

Borrar un elemento

Cuando queramos eliminar un elemento de un vector, deberemos desplazar los elementos que están después del elemento que hemos borrado hacia la izquierda. 

En el caso del ejemplo anterior, si queremos borrar el segundo elemento del vector de la tabla, tendremos que mover el tercer elemento a la segunda posición, el cuarto a la tercera, etc.

Contenido inicial del vector de la tabla	
5	7	12	26	31

Contenido final del vector de la tabla	
5	12	26	31

Igual que en el caso anterior, como último paso hay que reducir en 1 el atributo que contiene el tamaño de la tabla.

 

Ejemplo 04

En este ejemplo, se implementa la posibilidad de insertar elementos en una tabla que guarda los días de la semana, en una posición determinada. Para ello, habrá que realizar desplazamientos hacia la derecha de los elementos del vector de la tabla para que sigan quedando ordenados después de la inserción.

La función se utiliza para ordenar los días de la semana.

Pseudocódigo
	
C



const

    MAX_DAYS: integer = 7;

end const

type

    { Definition of the record tDay }
    tDay = record
        name: string;
        id: integer;
    end record

    { Definition of the table tWeek }
    tWeek = record
        days: vector[MAX_DAYS] of tDay;
        numDays: integer;
    end record

end type


action initialize(out week: tWeek)
    week.numDays := 0;
end action

action addDay(inout week: tWeek, in tDay day) 

    { numDays contains the number of
    elements of type tDay that the
    table tWeek contains }
    week.days[week.numDays+1] := day;

    { Once a new element tDay has been
    assigned to the table, we increase
    the value of numDays }
    week.numDays := week.numDays + 1;
end action

action addDaySorted(inout week: tWeek, in day: tDay)

    var
        i, j: integer;
        isAdded: boolean;
    end var


    isAdded := false;
    i := 1;
   
    { The id field of tDay will be used for sorting }
    while i ≤ week.numDays and not isAdded do
       
        { If the id of the tDay of the tWeek > id
        of the day parameter, from this point it
        will be necessary to shift the tDay record
        to the right. The goal is to get a free
        place, where the past tDay day will be
        added as a parameter to the action. }
        if week.days[i].id > day.id then
           
            { Shift of the tDays to the right,
            starting from the position where
            the day parameter passed by value
            will need to be added }
            for j := week.numDays+1 to i step -1 do
                week.days[j] := week.days[j-1]; 
            end for
         
            { The day parameter is added to its
            corresponding position, once the rest
            of the tDay records have been moved
            to the right. }
            week.days[j] := day;
            week.numDays := week.numDays + 1;
            isAdded := true;
        end if

        i := i + 1;
    end while

    { If at this point the tDay hasn't been
    added yet, that means it should go at
    the end of the tWeek table }
    if not isAdded then
        week.days[i] := day;
        week.numDays := week.numDays + 1;
    end if
end action

action show(in week: tWeek)

    var
        i: integer;

    end var
    for i := 1 to week.numDays do
        writeString(week.days[i].name);
    end for
end action

    tue.id := 2;
    wed.name := "wednesday";

    thu.id := 4;

    while the insertion for week will be

    addDay(week, thu);

#include <stdbool.h>

/* Definition of constants */

#define MAX_NAME 9+1

/* Definition of the record tDay */
typedef struct {
    char name[MAX_NAME];
    int id;
} tDay;

/* Definition of the table tWeek */
typedef struct {
    tDay days[MAX_DAYS];
    int numDays;
} tWeek;

/* Predeclaration of the actions */

/* Action that initializes the tWeek table,
* setting the numDays attribute to 0.
*/
void initialize(tWeek *week);

/* Action that adds a type tDay
* element to the tWeek table.
*/
void addDay(tWeek *week, tDay day);

/* Action that orderly adds a type tDay
* element to the tWeek table.
*/
void addDaySorted(tWeek *week, tDay day);

/* Action that displays the contents of
* the tWeek table on the screen.
*/
void show(tWeek week);

/* Main program */

    tue.id = 2;

    thu.id = 4;

    sat.id = 6;
    strcpy(sun.name, "sunday");
    sun.id = 7;
   
    /* We initialize the variables of type
    * tWeek.
    */
    initialize(&week);
    initialize(&weekSorted);
   
    /* We add the tDay variables in the week
    * and weekSorted tables out of order.
    * The difference between them will be
    * the method used to insert the tDay:
    * while the insertion for week will be
    * the usual one to add as the last element

    addDay(&week, mon);
    addDay(&week, wed);

    addDaySorted(&weekSorted, tue);
    addDaySorted(&weekSorted, fri);

    printf("\nUnsorted week : \n");
    show(week);
    printf("\nSorted week : \n");
    show(weekSorted);
    return 0;
}

/* Implementation of the actions */

void initialize(tWeek *week) {
    week->numDays = 0;
}

void addDay(tWeek *week, tDay day) {
    /* numDays contains the number of
    * elements of type tDay that the
    * table tWeek contains.
    */
    week->days[week->numDays] = day;

    /* Once a new element tDay has been
    * assigned to the table, we increase
    * the value of numDays.
    */
    week->numDays = week->numDays + 1;
}

void addDaySorted(tWeek *week, tDay day) {
    int i, j;
    bool isAdded;
   
    isAdded = false;
    i = 0;
   
    /* The id field of tDay will be used
    * for sorting.
    */
    for (i = 0; i < week->numDays && !isAdded; i++) {
       
        /* If the id of the tDay of the tWeek > id
        * of the day parameter, from this point it
        * will be necessary to shift the tDay record
        * to the right. The goal is to get a free
        * place, where the past tDay day will be
        * added as a parameter to the action.
        */
        if (week->days[i].id > day.id) {
           
            /* Shift of the tDays to the right,
            * starting from the position where
            * the day parameter passed by value
            * will need to be added.
            */
            for (j = week->numDays; j > i; j--) {
                week->days[j] = week->days[j-1];   
            }
         
            /* The day parameter is added to its
            * corresponding position, once the rest
            * of the tDay records have been moved
            * to the right.
            */
            week->days[j] = day;
            week->numDays = week->numDays + 1;
            isAdded = true;
        }
    }

    /* If at this point the tDay hasn't been
    * added yet, that means it should go at
    * the end of everything in the tWeek table.
    */
    if (!isAdded) {
        week->days[i] = day;
        week->numDays = week->numDays + 1;
    }
}

void show(tWeek week) {
    int i;
    for (i = 0; i < week.numDays; i++) {
        printf("%s\n", week.days[i].name);
    }
}

Resumen

 

En esta unidad se introducen dos esquemas algorítmicos diferentes que se utilizan para tratar secuencias de datos:
El de recorrido
El de búsqueda

Estas estructuras se pueden aplicar como un «patrón de solución» o «plantilla» para resolver determinados problemas en los que es necesario procesar secuencias de datos.

Ambos esquemas se basan en secuencias de control iterativas.

En el esquema de recorrido se procesan todos los elementos de la secuencia.

En el esquema de búsqueda se quiere determinar el elemento que cumple una determinada condición de búsqueda.
