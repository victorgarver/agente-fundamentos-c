Resumen

 

Introducción

Hasta aquí, hemos trabajado con programas que se formaban con una sucesión de expresiones: definimos unas variables y procesamos una expresión tras otra. Imaginemos que queremos hacer un programa que calcule las personas que cogen el autobús los días de lluvia y lo compare con el número de personas que lo coge cuando no llueve. El procesado de los datos será diferente en los días que llueve en comparación con los días que no llueve. ¿Cómo podemos hacerlo? 

En este apartado, exploraremos las estructuras de control alternativas, que permiten gestionar el flujo de ejecución de un programa en función de si se cumple o no una condición (en nuestro caso, que llueva o que no llueva). 

 

1. La toma de decisiones en el día a día

Imaginemos que queremos salir a la calle y miramos antes qué día hace. Así, si está lluvioso, llevaremos un paraguas para no mojarnos.

Pensad ahora que estamos en un restaurante y queremos pagar el menú que hemos disfrutado: si no tenemos suficiente efectivo, pagaremos con tarjeta; y, en caso contrario, usaremos el efectivo que llevamos.

Lo que acabamos de describir son ejemplos cotidianos de estructura de control alternativa, también conocida como estructura alternativa o condicional.

Como podéis intuir, usamos este tipo de estructura infinidad de veces a lo largo del día. Su funcionalidad nos permite tomar decisiones (llevamos o no paraguas, pagamos con efectivo o con tarjeta) basándonos en unas condiciones específicas (el día está lluvioso, llevamos suficiente efectivo).

Los dos ejemplos son estructuras alternativas simples. Se toma una decisión u otra en función de la evaluación de una única condición.

 

2. Estructura alternativa simple

El diagrama de flujo genérico de ejecución para una estructura alternativa simple es el siguiente:

 

El punto de entrada a una estructura de control alternativa es la evaluación de la condición, que siempre dará como resultado un valor booleano.

La condición puede ser una variable booleana, una expresión, una función o una combinación de todas estas. Lo importante es que el resultado final sea un valor booleano.

Ya conocemos las variables booleanas y las expresiones, pues las hemos tratado en unidades anteriores. De momento, no os preocupéis por las funciones, ya que las veremos más adelante.

Dependiendo del resultado de la evaluación de la condición (verdadero o falso), se pueden tomar dos caminos distintos. Si la evaluación da verdadero, se ejecutará el bloque de instrucciones de la izquierda (rectángulo azul de la figura anterior). En el caso contrario, si da falso, se ejecutará el bloque de instrucciones de la derecha (rectángulo gris de la figura anterior). En cada bloque de código, se ejecutarán una o más líneas de código (instrucciones). Un bloque de código nunca debería estar vacío.

Cuando termina la ejecución del bloque de instrucciones, ya sea el de la derecha o el de la izquierda, el flujo de la estructura alternativa finaliza también en el mismo punto.

3. Estructura alternativa compuesta
3.1. if ... else

Hasta aquí, hemos visto que la estructura de control alternativa nos ayuda en la toma de decisiones a partir de una condición inicial. Si nos paramos a pensarlo, solo nos ofrece un flujo de ejecución binario: o se cumple la condición y ejecutamos un bloque de instrucciones, o no se cumple y ejecutamos otro. Pero el mundo real no es tan simple y las condiciones que hay que analizar suelen ser más complejas.

Imaginemos que queremos controlar las personas que acceden a una determinada atracción de un parque. Solo pueden subir las personas mayores de edad. Los menores de más de 130 cm de altura pueden subir acompañados de una persona adulta.

Una posible forma de enfocar la resolución de este ejemplo sería la siguiente:

 

Como podéis observar, tenemos una estructura de control alternativa compuesta. Hemos añadido (anidado) un condicional dentro de otro para poder representar la situación que queremos tratar de una manera sencilla y fácil de comprender.

Una estructura alternativa compuesta (anidada) es aquella que se añade a un bloque de instrucciones de otro condicional. A su vez, puede contener otra estructura de control alternativa (anidada).

Las estructuras alternativas compuestas pueden llegar a tener un nivel de complejidad elevado. Por esta razón es indispensable que nuestros códigos tengan una indentación adecuada, de manera que facilite la lectura del flujo de ejecución y se evite la comisión de errores en su codificación.

Una posible manera de plantear este ejemplo sería mediante las siguientes dos condiciones:

Si la nota es válida o no.
Si la nota es superior o igual a 5.0.

3.2. switch

La estructura switch es una alternativa a la estructura alternativa compuesta if ... else cuando se trata de tomar decisiones basadas en el valor de una variable. Esta estructura, que permite simplificar el código y hacerlo más visual y fácil de mantener, es especialmente útil cuando tenemos múltiples condiciones que dependen del valor de una sola variable. Lo veremos más claro con un ejemplo:

Ejemplo 04

Dados dos números reales y un operador representado por un carácter, realizar la operación correspondiente si el operador es válido. En caso contrario, mostrar un mensaje informativo de error.

Como se puede observar, considerando únicamente los 4 valores correctos que puede tomar el operador, tenemos una estructura alternativa compuesta con muchas indentaciones. ¿Qué pasaría si en lugar de estos 4 operadores tuviéramos que tratar, por ejemplo:

Los 7 días de la semana?
Los 8 posibles movimientos de un caballo en un tablero de ajedrez?
Los 12 meses del año?

En todos estos casos tendríamos un programa con muchas indentaciones que haría cada vez más complicada su lectura y, por lo tanto, su comprensión y mantenimiento.

¿Cómo lo podemos simplificar? Utilizando la estructura switch.

Pseudocódigo
	
C

algorithm arithmeticOperatorSwitch

    var 
        a: real;
        b: real;
        operator: char;
        result: real;
        isValidOperator: boolean;
    end var

    writeString("Enter the first value: ");
    a := readReal();
    writeString("Enter the second value: ");
    b := readReal();
    writeString("Enter the operator: ");
    operator := readChar();
    
    isValidOperator := true;
    
    switch operator
        case operator = '+' then
            result := a + b;
        end case
        case operator = '-' then
            result := a - b;
        end case
        case operator = '*' then
            result := a * b;
        end case
        case operator = '/' then
            result := a / b;
        end case
        case default then
            isValidOperator := false;
        end case
    end switch
    
    if isValidOperator then
        writeString("The result is ");
        writeReal(result);
    else
        writeString("The operator is wrong!);
    end if

end algorithm

	
#include <stdio.h>
#include <stdbool.h>

int main() {

    float a;
    float b;
    char operator;
    float result;
    bool isValidOperator;

    printf("Enter the first value: ");
    scanf("%f", &a);
    printf("Enter the second value: ");
    scanf("%f", &b);
    printf("Enter the operator (+, -, *, /): ");
    getchar();
    scanf("%c", &operator);

    isValidOperator = true;

    switch(operator) {
        case '+':
            result = a + b;
            break;
        case '-':
            result = a - b;
            break;
        case '*':
            result = a * b;
            break;
        case '/':
            result = a / b;
            break;
        default:
            isValidOperator = false;
    }

    if (isValidOperator) {
        printf("The result is %.2f\n", result);
    } else {
        printf("The operator '%c' is wrong!\n");
    }

    return 0;
}

Pseudocódigo
	
C
	
Descripción

switch operator

Inicio de la estructura de control alternativa switch. La variable evaluada es operator.

        case operator = '+' then
            result := a + b;
        end case	
    case '+':
        result = a + b;
        break;

        case operator = '-' then
            result := a - b;
        end case

        result = a - b;
        break;

        case operator = '*' then
            result := a * b;
        end case	
    case '*':
        result = a * b;
        break;

        case operator = '/' then
            result := a / b;
        end case	
    case '/':
        result = a / b;
        break;
	Si se cumple que operator es igual al carácter '/', se dividen los dos reales.
        case default then
            isValidOperator := false;
        end case	
    case default:
        isValidOperator = false;
	

Cuando no se cumple ninguno de los casos anteriores, se ejecuta el bloque del caso default.

El caso default puede no existir, no es obligatorio utilizarlo.

end switch	
}

En este caso, cada bloque de código solo contiene una operación y un break. En otros casos, nos puede interesar que haya más de una operación antes del correspondiente break.

En una estructura switch en lenguaje C es necesario utilizar la sentencia break para romper el flujo de ejecución del programa. Si no se hace, el programa C continúa ejecutando los siguientes bloques de código aunque estén en otras secciones case.

4.1. Comparar una expresión con verdadero/falso
Ejemplo 05

Nos piden que hagamos un programa que muestre una de las leyes universales: «Si hoy hemos limpiado el coche, hoy lloverá». El programa recibe un valor booleano por el canal de entrada estándar que indica si el coche se ha limpiado hoy y que debe mostrar el mensaje que corresponda por el canal estándar de salida. 

La primera vez que codificamos un programa de estas características, podemos estar tentados a redundar innecesariamente la condición de la estructura de control alternativa:

Pseudocódigo
	
C

algorithm itRainsWrong

    var 
        isCleaned: boolean;
    end var

    writeString("Have you cleaned the car today? ");
    isCleaned := readBoolean();

    if isCleaned = true then
        writeString("It will rain today!");
    else
        writeString("It will not rain today");
    end if

end algorithm

	
#include <stdio.h>
#include <stdbool.h>

int main() {
    bool isCleaned;
    int intToBool;
    
    printf("Have you cleaned the car today? (0-FALSE, 1-TRUE) ");
    scanf("%d", &intToBool);
    isCleaned = (bool)intToBool;

    if (isCleaned == true) {
        printf("It will rain today! ");
    } else {
        printf("It will not rain today ");
    }
    
    return 0;
}

¿Por qué decimos que es redundante? Porque una variable booleana, una expresión, una función o una combinación de estas devuelve el resultado como valor booleano; por lo tanto, es redundante si lo queremos comparar con verdadero o falso.

La forma correcta para definir la condición sería la siguiente:

C

algorithm itRainsOk1

    var 
        isCleaned: boolean;
    end var

    writeString("Have you cleaned the car today? ");
    isCleaned := readBoolean();

        writeString("It will rain today!");
    else
        writeString("It will not rain today");
    end if

end algorithm

#include <stdbool.h>

    int intToBool;

        printf("It will rain today! ");
    } else {

    end var

        writeString("It will not rain today");
    else

4.2. Condicionales consecutivos
Ejemplo 06

Un hotel nos pide que programemos una aplicación para calcular el precio final de una habitación. El precio se calculará a partir del tipo de habitación y del tipo de cliente, que se indicará por el canal estándar de entrada.

Hay dos tipos de habitación:

Doble: a un precio de 120 € por noche.
Individual: a un precio de 75 € por noche.

Hay tres tipos de clientes:

Gold: tienen un 10 % de descuento en todas las habitaciones.
Silver: tienen un 5 % de descuento en todas las habitaciones.
Bronce: sin ningún descuento aplicable.

El programa debe mostrar el precio final de la habitación con el correspondiente descuento aplicado en caso de cumplirse las condiciones.

En una primera versión de nuestra solución, podemos plantear secuencialmente toda la combinatoria de tipo de habitación frente a tipo de cliente y hacer los cálculos correspondientes. Este planteamiento no es óptimo. Veámoslo:

Pseudocódigo
	
C

const
    DOUBLE_PRICE: real = 120.0;
    SINGLE_PRICE: real = 75.0;
    GOLD_DISCOUNT: integer = 10;
    SILVER_DISCOUNT: integer = 5;
end const

type

¿Por qué decimos que no es óptimo si calcula bien el precio final de la habitación? Porque se han construido seis condicionales independientes y consecutivos, de manera que siempre tienen que evaluar cada una de estas seis condiciones y decidir en cada caso si hay que ejecutar su correspondiente bloque de instrucciones. Esto no es necesario ni deseable, ya que aumenta el tiempo de ejecución.

Siempre que se pueda, se deben construir estructuras de control alternativas anidadas (excluyentes) para que solo se evalúen las condiciones imprescindibles y se obvien las restantes.

4.3. Condicionales vacíos
Ejemplo 07

Nos piden preparar un programa que indique si un carácter es una consonante. Para ello, se introducirá el carácter por el canal de entrada estándar y por el canal de salida estándar se mostrará un mensaje informativo en el caso de que se trate de una consonante.

Para solucionar el programa, podemos detectar si el carácter es una vocal, ya que hay menos opciones que tener bajo control —las consonantes son muchas más—. Usando una estructura de control alternativa tendremos que, en el caso de que sea una vocal, no se hará nada, mientras que, en el caso contrario, mostrará el literal correspondiente por el canal de salida estándar.

Pseudocódigo
	
C

algorithm isConsonantWrong

    var 
        letter: char;
    end var

    writeString("Enter a letter: ");
    letter := readChar();

    if letter = 'a' or letter = 'e' or 
        letter = 'i' or letter = 'o' or
        letter = 'u' then
    else
        writeString("The letter is a consonant.");
    end if

end algorithm

	
#include <stdio.h>

int main() {

    char letter;

    printf("Enter a letter: ");
    scanf("%c", &letter);

    if (letter == 'a' || letter == 'e' ||
        letter == 'i' || letter == 'o' || 
        letter == 'u') {
    } else {
        printf("The letter is a consonant.");
    }

    return 0;
}

Este planteamiento es incorrecto, ya que no podemos dejar vacío ningún bloque de instrucciones definido. Podéis observar que la estructura condicional tiene un then sin ninguna instrucción. También sería incorrecto si el bloque del else estuviera definido y vacío.

¿Cómo podemos solucionarlo? Redefiniendo la condición para que el then no quede vacío:

Pseudocódigo
	
C

algorithm isConsonantOk

    var 
        letter: boolean;
    end var

    writeString("Enter a letter: ");
    letter := readChar();

    if letter ≠ 'a' and letter ≠ 'e' and
        letter ≠ 'i' and letter ≠ 'o' and 
        letter ≠ 'u' then
        writeString("The letter is a consonant.");
    end if

end algorithm

    printf("Enter a letter: ");
    scanf("%c", &letter);

        letter != 'i' && letter != 'o' && 
        letter != 'u') {
        printf("The letter is a consonant.");
    }

    return 0;
}

Ahora, podéis observar que el único flujo posible de ejecución del condicional no está vacío y, por lo tanto, es correcto.

 

4.4. Interrumpir el flujo de ejecución
Ejemplo 08

Nos piden que creemos un programa que, a partir de un código ASCII pasado por el canal estándar de entrada, muestre por el canal estándar de salida el carácter que lo representa. Se deben tratar únicamente los códigos comprendidos entre el 65 y el 90, que corresponden a las letras mayúsculas. Cualquier otro código debe mostrar un mensaje de error y finalizar el programa.

A menudo, nos piden interrumpir la ejecución de un programa en caso de que se dé alguna situación (por ejemplo, un error en la entrada de datos). A nivel de pseudocódigo, no hay ninguna función ni sentencia pensada para efectuar esta acción de manera explícita. En el siguiente planteamiento incorrecto, se intenta simular mediante la sentencia end algorithm / return 0:

Pseudocódigo
	
C

algorithm capsFromCodeWrong

    var 
        code: integer;
    end var

    writeString("Enter a code (65...90): ");
    code := readInteger();

    if code < 65 or code > 90 then
        writeString("Wrong code.");
        end algorithm
    else
        writeString("The capital letter is: ");
        writeChar(codeToChar(code));
    end if

end algorithm

	
#include <stdio.h>

int main() {

    int code;

    printf("Enter a code (65...90): ");
    scanf("%d", &code);

    if (code < 65 || code > 90) {
        printf("Wrong code.");
        return 0;
    } else {
        printf("The capital letter is: %c ", (char)code);
    }

    return 0;
}

La solución correcta implica montar la estructura alternativa, de manera que, cuando se produzca el error, no se ejecute ninguna otra sentencia.

Un diseño correcto, y más elegante, tendría las condiciones inversas, y dejaría siempre los errores y la salida del algoritmo dentro del bloque else: 

Pseudocódigo
	
C

algorithm capsFromCodeOk

    var 
        code: integer;
    end var

    writeString("Enter a code (65...90): ");
    code := readInteger();

    if code ≥ 65 or code ≤ 90 then
        writeString("The capital letter is: ");
        writeChar(codeToChar(code));
    else
        writeString("Wrong code.");
    end if

end algorithm

	
#include <stdio.h>

int main() {

    int code;

    printf("Enter a code (65...90): ");
    scanf("%d", &code);

    if (code >= 65 && code <= 90) {
        printf("The capital letter is: %c ", (char)code);
    } else {
        printf("Wrong code.");
    }

    return 0;
}

 

Resumen

 

La estructura alternativa es una estructura básica para controlar el flujo de ejecución de un programa. 
La estructura alternativa se basa en las palabras reservadas if/else, tanto en pseudocódigo como en C.
La estructura alternativa switch se utiliza cuando se quieren tomar decisiones en función de los valores de una única variable.
Hemos comentado una serie de ejemplos y buenas prácticas que son muy aconsejables a la hora de generar pseudocódigo y programas.
